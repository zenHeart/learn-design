# 我的设计哲学：清晰、克制与有效空间

我的界面首先要让人看清、找到、完成手上的工作。视觉风格应当稳定，空间应当服务于内容。优化一个已有产品时，先解决阅读和使用中的阻力，再决定是否需要新的形式。

本文是个人偏好与判断方法，源于 2026-09-09 的工作台设计反馈 [S1]。它不是无障碍标准，也不是对所有产品都成立的规则。文中的实现建议仍需在具体产品中验证。

## 1. 保持视觉身份，改进阅读体验

我认可一个主题后，优化应延续它的色彩、材质感、标题性格和结构语言。字体太小、看着模糊时，应先检查字号、字重、字体回退、对比度和实际缩放，不把换主题当作修复。

可读性是密度的前提。不能为了多放几行内容持续缩小字，也不能把所有文字一起放大而破坏层次。正文、控件、辅助信息各有稳定的尺度，中文和英文都要检查。

**检查方式：** 在正常缩放下读完一张任务卡，能否直接分辨标题、状态与属性？低频信息虽然次要，是否仍能读清？

## 2. 空间围绕当前工作分配

我希望工作区尽早出现可操作的内容。顶部有大片空白，而下面又另起一块标题和说明时，应重新安排信息位置。页面标题可以进入应用顶部；与当前动作有关的操作应靠近内容。

留白有价值，但需要承担分组、呼吸或突出重点的作用。没有内容的“北极星”标签不能长期占据一条固定区域。有真实目标时展示目标；没有时收起占位。不要为填空编造目标。

**检查方式：** 每一个常驻区域是否帮助定位、判断或操作？删掉后毫无影响的重复文字，是否值得继续占用空间？

## 3. 说明按使用频率安排

页面名称、高频筛选与关键状态需要直接可见。数据来源、术语解释和完整使用说明可以放进有明确名称、键盘可达的说明入口。首次使用和异常恢复时，再在相关位置展开必要信息。

折叠说明不能隐藏权限边界、异常或作出决定所需的信息。需要处理的错误仍应直接呈现。

**检查方式：** 熟练使用者能否不重复阅读说明就开始工作？初次使用者是否仍能找到解释？

## 4. 默认视图回应真实习惯

我的工作台以“本周、全部范围”为起点，帮助我先看全貌，再缩小到工作、个人、项目或执行者。这个选择是我的使用习惯，不是所有任务产品的默认答案。

显式筛选链接应保留用户的选择。刷新、前进和后退不能悄悄恢复默认条件。

## 5. 从信息结构解决布局问题

优化顺序是：确定页面要支持的工作，区分高低频信息，去掉重复表达，安排分组和位置，最后调整字阶、间距和边框。不要在结构没有理顺时只调 padding。

桌面看板可以保持稳定的状态列；窄屏需要重排内容。提高空间利用率不等于把所有信息塞进首屏，也不等于所有空列都必须填满。状态结构的可预测性同样有价值。

## 6. 用实际界面验证品味

截图用于发现问题，修改后的真实页面用于判断是否修复。需要检查长标题、空状态、较多记录、亮暗主题和窄屏；字号与空间的取舍，以阅读和操作是否顺畅来判断。

每次验证分别记录“实现了什么”和“证据能证明什么”。主观上更舒服可以成为偏好；未经测量，不能写成效率提升了某个百分比。

## 本次落地的可调整参数

下面是对上述原则的实现建议，不是永久规则，也不是 WCAG 的字号门槛：

| 角色 | 初始建议 | 需要观察的取舍 |
| --- | --- | --- |
| 正文与任务标题 | 16 CSS px，行高约 1.6 | 长标题占用与阅读舒适度 |
| 控件与次级信息 | 14 CSS px | 可辨认性与工具栏换行 |
| 辅助文字与编号 | 13 CSS px 起 | 对比度、字体差异与可读性 |
| 顶部页面上下文 | 精简标题与真实目标 | 避免重复页头，窄屏保留定位 |
| 长说明 | 明确命名的按需入口 | 可发现性与常驻空间 |

产品的具体 token、代码和验收证据属于产品仓库；这里保留可迁移的判断方法，不复制私有任务、内部截图和运行数据。
