# 学习 Agent 与知识库 Agent 的产品交互合同

> 本页把设计判断连接到一个可验证的业务任务：学习者或业务人员向 Agent 提出目标，Agent 读取知识、调用工具、产生中间证据，并在必要时把结果交给人确认。它服务于 Learn 系列、Pi Agent 扩展和企业知识库 Agent 的共同底层。

本文是待实施的设计与验收合同，不表示 Learn 站点、课程或 Pi 扩展已经实现这些能力。页面结构、五维掌握和证据要求属于本项目的设计选择；Pi API、MCP 与无障碍事实分别以文末 [S1]–[S4] 为依据。关联 [Workflow #651](https://github.com/zenHeart/workflow/issues/651)。

## 1. 先定义任务，再定义界面

任何 Agent 功能先写一份任务合同：

| 字段 | 要回答的问题 |
| --- | --- |
| 终局任务 | 用户最终要独立完成什么工作？ |
| 输入约束 | 资料、权限、时间、成本、数据新鲜度是什么？ |
| 允许动作 | Agent 可以检索、写入、调用哪些工具？ |
| 副作用 | 哪些动作会修改数据、发送消息或消耗费用？ |
| 完成证据 | 不读 Agent 自述，怎样判断任务确实完成？ |
| 失败分类 | 环境、数据、权限、检索、模型、工具还是用户决策？ |
| 人工门 | 哪些节点必须由人批准、复核或验收？ |

“生成一个回答”不能作为完成标准。知识库 Agent 至少要返回来源定位、检索范围、结论置信度和未解决问题；学习 Agent 至少要留下独立完成、调试、迁移和延迟复测证据。

## 2. 学习 Agent 的最小交互闭环

学习页面首屏只回答四件事：

1. 现在做什么；
2. 为什么做；
3. 通过标准是什么；
4. 失败后怎样缩小任务。

节点工作区按下面顺序组织：

```text
预测 / 回忆
→ 最小解释
→ 可运行示例
→ 补全
→ 独立构建
→ 故障注入
→ 调试
→ 迁移
→ 教回
→ 延迟复测
```

完整知识地图用于导航和来源追溯，不能替代学习动作。已掌握的节点从当前路线移除，但仍保留在图谱中，避免把个人路线误当成完整课程。

每个节点至少有五个掌握维度：

- Explain：能解释因果、不变量和边界；
- Perform：能在新起点独立完成；
- Debug：能定位陌生失败并修复；
- Transfer：能迁移到新输入或新约束；
- Retention：经过延迟后仍能重建。

## 3. 知识库 Agent 的最小交互闭环

知识库 Agent 的页面应把“回答”拆成可检查的执行链：

```text
问题澄清
→ 选择来源与权限
→ 检索 / 重排
→ 形成候选结论
→ 标注证据与不确定性
→ 检查工具权限和本次授权范围
→ 高影响动作取得有效人工批准
→ 执行已授权工具
→ 输出结果与回放记录
```

回答卡片至少包含：

- 结论；
- 证据片段和精确来源；
- 来源时间、版本或文档提交；
- 使用过的工具和参数；
- 未找到的信息；
- 可复现的下一步；
- 是否产生了外部副作用。

引用应靠近结论。长文只作为展开内容，不能把关键证据埋在页面底部。

## 4. Pi Agent 的定制化边界

Pi 官方扩展接口提供自定义工具、命令、事件处理、会话条目、UI 及提供商注册；工具执行前事件可以阻止调用。[S1] 本页核验的固定提交也支持配置 MCP 服务及通过扩展注册 MCP 服务，MCP 接入方式必须与实际安装版本一致。[S2] 这些能力不自动构成权限隔离：扩展与 Pi 进程拥有相同的操作系统权限，只能加载可信扩展，应用内钩子不能替代操作系统沙箱。[S1]

在这些接口之上，本项目采用三层设计：

| 层 | 内容 | 变更方式 |
| --- | --- | --- |
| Skill | 稳定的方法、判断标准、领域知识 | 版本化资产 |
| Extension | 工具注册、事件处理、UI 和权限逻辑 | TypeScript 代码 |
| Project Profile | 当前仓库、目标、允许路径、数据源和人工门 | 项目配置 |

学习 Agent 不应把个人学习状态写入 Skill；知识库 Agent 不应把真实凭据和业务资料写入公共 Prompt。两者都应通过事件记录和私有运行时状态实现持久化。

Pi 扩展应优先提供以下通用能力：

- `source_search`：按来源、版本、权限搜索；
- `evidence_read`：读取精确来源并返回定位；
- `task_checkpoint`：记录可恢复阶段；
- `evaluate_artifact`：执行确定性测试或评分规则；
- `human_gate`：请求人工批准；
- `session_recap`：生成可追溯的任务摘要。

本项目要求副作用动作绑定可核验授权；超出既有授权范围时，先取得批准再执行。工具结果必须保留调用 ID，失败后先读状态再决定是否重试。MCP 工具规范使用 SHOULD 推荐保留人工参与，并不规定唯一交互界面；上述授权规则是本项目的具体合同。[S3]

## 5. 面向学习站点的页面结构

统一学习站点可以复用下面的页面模型：

```text
目标页：终局任务、岗位和约束
路线页：当前依赖锥、已掌握节点、阻塞节点
节点页：解释、练习、代码、故障、迁移、复测
证据页：作品、测试、评分、来源和失败记录
复习页：即将到期的脆弱节点及原因
导出页：当前路线的 Markdown、PDF、EPUB 快照
```

页面状态必须由事件推导，不能由前端复选框直接写入“已掌握”。

## 6. 统一的失败反馈

反馈始终包含三部分：

- 目标：这道题要证明什么；
- 差距：你的证据在哪一步失败；
- 下一步：只给一个最小修复动作。

错误标签应区分：

```text
概念缺口 / 操作缺口 / 调试缺口 / 迁移缺口 /
数据问题 / 权限问题 / 环境问题 / 工具问题 / 需求不清
```

同一错误连续出现时，路线应该回退到最近的先修节点，而不是继续生成更长的解释。

## 7. 与 Learn、Workflow 和 Career 的连接

Learn 负责能力图谱、诊断、课程包和掌握闸门；Workflow 负责任务状态、执行、报告、核验和回放；Career 负责岗位目标、面试要求、作品映射和差距报告。

一个真实的“Python 知识库 Agent”面试项目应同时验收：

- Python 类型、异常、异步和测试；
- FastAPI 或等价服务；
- 文档切分、embedding、混合检索和引用；
- 工具调用、MCP、状态持久化和重试；
- 权限过滤、提示注入防护和人工确认；
- 评测集、trace、延迟、成本和失败率；
- Docker、CI/CD、部署和运行手册；
- 面试者能解释设计取舍，并修复故意注入的故障。

这套合同也适用于 Java 和 Go：语言生态不同，但任务、证据、失败分类、人机边界和验收结构保持一致。

## 8. 发布与审计门禁

发布学习包或 Agent 扩展前必须检查：

- 所有关键结论都有来源定位；
- 课程节点都有无提示任务和失败证据；
- 工具调用可回放且副作用可识别；
- 权限和敏感路径有门禁；
- 站点按 WCAG 2.2 的键盘操作与状态信息要求核验，并提供可访问的文本路径；[S4]
- PDF/EPUB 与网页使用同一版本的源内容；
- 个人画像、凭据和业务原文没有进入公共产物；
- 发布版本可由 commit、schema 和构建命令复现。

这份合同把“设计好看”“Agent 能回答”和“学习完成”统一转换成可观察的任务行为和证据链。
